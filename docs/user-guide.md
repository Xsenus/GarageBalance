# Руководство пользователя

Инструкция для ежедневной работы в GarageBalance. Документ описывает рабочие разделы интерфейса: вход, справочники, тарифы, платежи, отчеты, импорт, историю изменений и "Что нового".

## 1. Вход

- [ ] Открыть локальный адрес `http://127.0.0.1:5173` или стенд `https://sgk.blagodaty.ru`.
- [ ] Ввести email и пароль.
- [ ] Если система запускается впервые, создать первого администратора через стартовую форму. При одновременной отправке с нескольких вкладок будет создана только одна первая учётная запись.
- [ ] Пароль должен быть не короче 8 символов.
- [ ] Если форма показывает validation summary, исправить отмеченные поля до повторной отправки.
- [ ] Если вход временно ограничен после нескольких ошибок, дождаться окончания ограничения или обратиться к администратору.
- [ ] Если с общего адреса отправлено слишком много форм входа и показано сообщение «Повторите попытку позже», дождаться окончания защитного интервала; повторные нажатия не ускоряют вход.
- [ ] После истечения срока сессии система автоматически очистит авторизацию и вернет форму входа; войти повторно, чтобы продолжить работу.

## 2. Права и видимость разделов

Разделы появляются по правам пользователя:

- Боковая панель доступна каждому вошедшему сотруднику, а недоступные разделы полностью скрываются из главного меню и панели; перейти в них по внутренней ссылке также нельзя.

- `users.manage` открывает "Пользователи".
- `dictionaries.read` открывает "Справочники" и "Тарифы и сборы".
- `tariffs.manage` разрешает изменять данные в разделе "Тарифы и сборы".
- `payments.read` открывает "Платежи".
- `reports.read` открывает "Отчеты", но для фильтров отчеты также требуют `dictionaries.read`.
- `import.run` открывает "Импорт".
- `audit.read` открывает "История изменений".
- `app_releases.manage` показывает права для "Что нового".

Если права нет, интерфейс показывает состояние "раздел недоступен" и не загружает защищенные данные этого раздела.

## 3. Пользователи и безопасность аккаунта

Раздел "Пользователи" доступен сотруднику с разрешением `users.manage`.

- [ ] Создать сотрудника: email, имя, одну или несколько ролей и пароль.
- [ ] Проверить выбранные роли по матрице прав перед сохранением. Обязательные права чтения добавляются автоматически вместе с использующим их правом.
- [ ] Отключить сотрудника при увольнении или смене доступа. Его открытые сессии прекращаются сразу.
- [ ] Обычные изменения пользователя и прав роли сохраняются сразу; отдельное подтверждение остаётся при отключении, удалении и восстановлении доступа.
- [ ] Не отключать последнего активного администратора: система сохраняет это ограничение и при одновременной работе нескольких администраторов.
- [ ] Для собственного пароля открыть "Безопасность аккаунта", ввести текущий пароль, новый пароль и повтор. После успешной смены текущая сессия завершится; войдите с новым паролем.
- [ ] В разделе "Настройки" выбрать внутреннюю вкладку "Безопасность"; остальные группы параметров будут добавляться в эту боковую навигацию отдельно.
- [ ] Администратор может открыть вкладку "Отображение" и включить общую ведомость платежей при входе в раздел; стандартно этот режим выключен.
- [ ] Чтобы понять назначение параметра на вкладке "Отображение", открыть значок `?` рядом с его названием мышью или клавишей Tab. Справка не изменяет значение переключателя.
- [ ] В той же вкладке администратор может включить название фонда под наименованием услуги в главной таблице раздела "Тарифы и сборы". По умолчанию название фонда скрыто.
- [ ] Только системный администратор видит вкладку `Рабочая дата`. Она используется для тестирования начислений, просрочки, должников и периода отчётов по умолчанию; перед применением система показывает влияние изменения в отдельном окне подтверждения. Справка `?` возле даты и дня начисления зарплаты объясняет действие каждого параметра. После проверки администратор обязан вернуть автоматическую системную дату. Подробный сценарий приведён в `docs/admin-operations-guide.md`.
- [ ] Только системный администратор видит вкладку `Касса и счёт`. На ней отображаются текущие доступные остатки кассы и банковского счёта; стартовые остатки с этой формы не редактируются.
- [ ] Для внесения денег, не являющегося платежом гаража, выбрать у кассы или счёта `Пополнить`; для уменьшения остатка — `Списать`. Операция оформляется в отдельном окне: указать дату, сумму и причину. Списание сверх доступного остатка блокируется.
- [ ] После проведения операции проверить всплывающее уведомление в нижней части экрана и новую строку таблицы. В истории показываются дата и время проведения, счёт, направление, сумма и причина; запись также сохраняется в истории изменений.
- [ ] Интеграции 1С Fresh и печати временно не показываются ни одной роли. Администратор может открыть `Настройки` → `Интеграции`, безопасно сохранить API-ключ DaData и использовать подсказки адресов в карточках гаражей и поставщиков; сохранённый ключ обратно не отображается.
- [ ] Не передавать пароль в открытых сообщениях.

## 4. Справочники

Раздел "Справочники" используется для базовых данных учёта: владельцев, гаражей, видов поступлений, статей расходов и единиц измерения. Поставщики и тарифы ведутся только в профильных разделах, чтобы одна и та же запись не редактировалась в двух местах.

- [ ] Владельцы: ФИО, телефон, email и примечание.
- [ ] Телефоны владельцев, поставщиков и контактов вводить в российском формате `+7 (999) 123-45-67`. Допускается начать ввод с `8`, `+7` или с десяти цифр без кода страны: форма расставит скобки и дефисы автоматически. Пустое поле допустимо, неполный номер сохранить нельзя.
- [ ] При создании гаража отдельно указывать `Начальный баланс` и входящую часть, которая уже просрочена. Начальная просрочка не может быть отрицательной или превышать положительный начальный баланс; после появления финансовой истории эти исходные значения изменяются только отдельной корректировкой с причиной.
- [ ] При вводе адреса выбрать подходящий вариант DaData. После выбора адрес останется в поле без дополнительной успешной подписи; сообщения поиска, отсутствия вариантов и недоступности сервиса остаются видимыми.
- [ ] На вкладке `Контрагенты` → `Гаражи` использовать фильтр по части номера и диапазоны количества людей/этажей; кнопка `Сбросить фильтры` очищает все три условия, а режим `Показать должников` пересекается с ними.
- [ ] На вкладке `Контрагенты` → `Поставщики` отображается общий список без переключателя должников. Для проверки задолженности отсортировать одноимённую колонку.
- [ ] Финансовый отчёт открывать из карточки или таблицы уже сохранённого гаража, поставщика либо сотрудника. При первом открытии система сама выбирает весь период от первой активной финансовой записи до текущего или последнего будущего месяца; даты затем можно изменить вручную либо выбрать быстрый период `Текущий месяц`, `Текущий год` или `Предыдущий год`. В форме новой записи этой кнопки нет: сначала сохранить карточку, затем открыть её повторно.
- [ ] В разделе `Отчёты` → `По гаражам` найти нужные гаражи по номеру или ФИО владельца и отметить их флажками. Выбранный гараж можно убрать отдельной кнопкой, а весь фильтр — действием `Очистить`; если карточек нет, отчёт охватывает все гаражи. Подробная таблица показывает услугу перед начислением. Разница считается как начисления минус поступления; при группировке услуги объединяются в одну строку по гаражу и месяцу.
- [ ] В форме сотрудника выбрать отдел из списка. Если нужно перейти к ФИО, ставке или другому полю без изменения отдела, достаточно кликнуть вне списка: он закроется, а прежний выбор сохранится.
- [ ] В таблице отделов рабочими колонками являются `Отдел` и `Действия`. Отдельного статуса `Активен` нет; архивный отдел выделяется приглушённой строкой и предлагает действие восстановления.
- [ ] Группы поставщиков и поставщиков создавать и изменять в разделе `Контрагенты` → `Поставщики`; отдельного дублирующего редактора в `Справочниках` нет.
- [ ] При создании поставщика поле `Начальная задолженность` доступно для ввода прямо в основной карточке. После появления финансовой истории исходную сумму изменять через обычное редактирование нельзя: используется отдельная корректировка с причиной.
- [ ] Телефон и почта первого действующего контакта показаны отдельными полями в основной карточке поставщика. Их можно изменить как сверху карточки, так и в строке таблицы `Контакты`: оба места редактируют одну запись и сразу синхронизируются. ФИО, должность, статус и комментарий изменяются в строке контакта. При открытии сохранённой карточки система отдельно загружает все контакты выбранного поставщика, поэтому значения не зависят от размера общего справочника.
- [ ] В таблице поставщиков длинные названия, услуги, ФИО и адреса почты переносятся только внутри своей колонки. Телефон показывается целиком, задолженность выровнена по центру, а на узком экране горизонтальная прокрутка остаётся внутри таблицы и не растягивает страницу.
- [ ] Виды поступлений: членские, целевые, вступительные и другие поступления.
- [ ] Статьи расходов: электроэнергия, мусор, вода, банковские и прочие расходы.
- [ ] Единицы измерения: обозначения, которые предлагаются при добавлении и изменении услуги. Тарифы и тарифные периоды создавать и изменять в разделе `Тарифы и сборы`.
- [ ] Архивирование скрывает запись из рабочих списков, но не удаляет историю и audit.
- [ ] Перед архивированием система показывает подтверждение.
- [ ] Если запись архивирована ошибочно, включить "Показывать архивные", открыть действие "Вернуть" и подтвердить восстановление.
- [ ] Если восстановление показывает конфликт, сначала проверить активную запись с тем же номером, названием или кодом и исправить дубль.
- [ ] Изменения основной карточки поставщика сохраняются сразу по кнопке `Сохранить`, без второго окна со сравнением полей. Удаление или восстановление контакта по-прежнему требует отдельного подтверждения, а для удаления необходимо указать причину.

## 5. Тарифы и сборы

Раздел "Тарифы и сборы" доступен пользователям с `dictionaries.read`; для изменения данных требуется `tariffs.manage`.

- [ ] Строки `Зарплатный фонд` формируются автоматически по действующим отделам из `Контрагенты` → `Персонал`. Значение каждой строки равно сумме ставок активных сотрудников отдела; вручную менять или удалять эти строки в таблице тарифов не нужно.
- [ ] При добавлении услуги включить "Регулярные платежи" только для услуги, которая начисляется по расписанию. Для регулярной услуги слева указываются настройки и параметры начисления, а справа — начальная дата и тариф либо пороговая сетка. Если переключатель выключен, указать стоимость: после сохранения услуга появится в таблице "Нерегулярные платежи" без признаков счетчика и пороговой тарификации.
- [ ] В таблице `Нерегулярные платежи` состояние временно выключенной записи показывается подписью `Отключён`. Название не зачёркивается; прежние начисления и оплаты такой записи продолжают храниться в финансовой истории.
- [ ] Для регулярной услуги выбрать фонд поступления, единицу измерения, периодичность, срок оплаты и перенос долга. При сохранении система одним действием создаст собственный тариф, свяжет его с услугой и сразу покажет введённую ставку в основной таблице.
- [ ] Единицу измерения выбирать в форме добавления или изменения услуги. При открытии поля всегда показывается полный справочник; во время ввода список не сокращается, а автоматически прокручивается к найденному обозначению. Поле также позволяет ввести новое значение; при сохранении оно автоматически добавляется в справочник. Пустые значения и дубли без учёта регистра и пробелов не создаются.
- [ ] Выбрать периодичность регулярной услуги: `Ежемесячно` создаёт начисление каждый месяц, `Ежегодно` — один раз в выбранном месяце начисления.
- [ ] Для ежемесячной услуги указать только число оплаты: срок наступит в следующем месяце после начисления. Для ежегодной услуги дополнительно выбрать календарный месяц оплаты; срок относится к тому же учетному году, поэтому поздно сформированное начисление может сразу оказаться просроченным.
- [ ] Чтобы изменить действующую регулярную услугу, нажать кнопку с карандашом в её основной строке. В одной форме можно исправить название, фонд поступления, тарифные периоды, единицу измерения, расписание, срок оплаты, перенос долга и признаки счётчика/порогов. Тип регулярной услуги после создания не меняется; при ошибке сохранения форма остаётся открытой и сохраняет введённые значения для повтора.
- [ ] Проверить признаки "Пороговая тарификация" и "По счётчику" в основной строке каждой услуги. Быстрое переключение или изменение ставки создаёт новую версию с текущей датой и не переписывает прошлый период или уже настроенные будущие периоды. Для произвольных дат открыть услугу карандашом и изменить таблицу периодов. В служебных строках и отдельных тарифных порогах признаки намеренно не повторяются.
- [ ] При включении "По счётчику" система создаёт для услуги собственный независимый счётчик и совместимую версию тарифа. Выбранная единица измерения при переключении не изменяется. Услуга появляется отдельным пунктом в разделе "Показания" со своим названием и единицей измерения; внесённый расход умножается на её ставку либо рассчитывается по её порогам. Показания разных услуг не смешиваются, даже если обе используют одинаковый тип тарифной сетки.
- [ ] Сверить основную строку и карточку услуги: показывается наименование услуги без технической приписки режима, а ставка, единица и признаки расчёта берутся из сохранённых настроек этой же услуги. Единица в таблице доступна только для чтения и изменяется через действие с карандашом. После сохранения формы новое значение сразу появляется в таблице без перезагрузки страницы.
- [ ] В основной таблице читать единицу перед значением: колонки идут как `Основание`, `Ед.`, `Значение / ставка`. На узком экране таблица сохраняет этот порядок при горизонтальной прокрутке.
- [ ] Срок перехода долга в просроченный указывать в компактной колонке `Просрочка, дн.` основной строки услуги. Отдельные повторяющиеся строки для этой настройки больше не показываются; изменение по-прежнему требует подтверждения и сохраняется вместе с настройкой услуги.
- [ ] Для прекращения новых регулярных начислений нажать кнопку деактивации в основной строке услуги и обязательно указать причину. Подтверждение заранее напоминает: уже созданные начисления и связанные платежи сохраняются, задолженность можно погашать, а операции остаются в отчётах и истории изменений. После восстановления услуга участвует только в будущих начислениях; прошлые периоды автоматически не пересчитываются.
- [ ] Проверить, что деактивированная услуга исчезла из рабочего списка. Для просмотра таких записей открыть вкладку `Удалённые услуги`: они показаны отдельно, только для чтения, и не мешают работе с действующими тарифами и услугами.
- [ ] Чтобы вернуть услугу в работу, во вкладке `Удалённые услуги` нажать действие восстановления и подтвердить его. После успешного ответа система сама откроет действующий список: услуга снова доступна для редактирования и будущих начислений, но прошлые периоды автоматически не пересчитываются.
- [ ] Для любой услуги с включённым режимом "По счётчику" можно включить "Пороговую тарификацию". В форме сразу появляется список явных диапазонов `От — До` и цена за единицу. Первая ступень начинается с нуля, а начало каждой следующей автоматически равно верхней границе предыдущей плюс один. Последняя ступень действует без верхней границы. Система выбирает одну ставку по текущему показанию счётчика и умножает на неё весь расход выбранного месяца; расход не делится прогрессивно между ступенями. При выключенном счётчике пороговая тарификация недоступна, потому что без показания нечем определить ступень.
- [ ] Тариф настраивается внутри карточки услуги — отдельные поля старого вида поступления, начисления поставщику, фонда расходования и технической базы расчёта пользователю не требуются. В таблице `Изменение тарифов по периодам` указать начальную дату, конечную дату при необходимости и ставку. Пустая граница означает действие без ограничения с соответствующей стороны; периоды не должны пересекаться.
- [ ] Для пороговой услуги нажать `Добавить порог`, указать верхнюю границу в единице выбранной услуги и ставку. Новая ступень сохраняется в тарифе и участвует в начислениях; для удаления добавленного порога укажите причину, которая попадёт в историю изменений.
- [ ] При изменении тарифной сетки неоплаченные начисления выбранного периода могут быть пересчитаны из формы платежей гаража; начисления с любой активной оплатой остаются неизменными. Для нового месяца система выбирает ставку по датам действия, а не по текущему значению основной таблицы.
- [ ] При объявлении сбора выбрать `Назначение поступления` и режим `Все гаражи` либо конкретных участников. В списке доступны действующие назначения, связанные с фондом; выбранное назначение определяет фонд, в который будут направлены оплаты по сбору. Можно первым указать как `Сумму взноса`, так и `Сумму сбора`: второе значение рассчитывается автоматически по числу участников. Если общая сумма не делится поровну до копейки, последний взнос ограничивается точным остатком. Для режима `Все гаражи` система использует полное количество активных гаражей, даже если рабочий список загружается частями. Сохраненный сбор сразу появляется в списке `Объявленные сборы` и не исчезает, если одновременно завершилась фоновая загрузка списка. До первого начисления можно уточнять состав и назначение поступления; после начисления эти финансовые связи блокируются для сохранения истории.
- [ ] Все одновременно действующие сборы начисляются автоматически за текущий рабочий месяц вместе с регулярными услугами. В первый месяц общий сбор применяется ко всем активным гаражам, а выборочный — только к указанным участникам. В следующие месяцы начисление повторяется только для участников, у которых предыдущие начисления по этому сбору оплачены не полностью: частичная оплата не исключает участника, а полная оплата исключает его из новых начислений. Правило действует до закрытия сбора. Сбор, объявленный в середине месяца, относится к этому же учетному месяцу; повторный запуск в одном месяце не создаёт дубли.
- [ ] Открыть гараж в разделе `Платежи` и проверить строку действующего сбора: она появляется автоматически, отдельной кнопки доначисления больше нет. Обычная сумма равна взносу, но если до общего плана осталось меньше, строка показывает только остаток.
- [ ] При оплате сбора можно внести больше обычного взноса, вплоть до всего оставшегося плана. После достижения общей суммы сбор закрывается автоматически и при повторном открытии ранее рассчитанной, но неоплаченной платёжки его строка исчезает.
- [ ] После создания начислений не менять исторический состав сбора: система отклонит замену участников, но позволит исправить остальные реквизиты сбора.
- [ ] Чтобы завершить сбор, нажать действие `Закрыть сбор`. При полностью оплаченном плане комментарий необязателен; если распределённые оплаты меньше суммы сбора, закрытие считается досрочным и требует комментарий. После закрытия автоматическое и ручное доначисление блокируются, но прежние начисления, оплаты, задолженность, отчёты и audit сохраняются. Архивированный закрытый сбор можно вернуть в рабочий список только для просмотра и истории — начисления не возобновятся.

## 6. Платежи и начисления

Раздел "Платежи" содержит поступления, выплаты, начисления, начисления поставщикам и показания счетчиков.

- [ ] На вкладке `Поступления` найти один гараж через поиск; без выбранного гаража ведомость поступлений не загружается. Выбор другого результата сразу заменяет текущую карточку. На вкладке `Выплаты` поиск и карточка гаража не показываются: форма поставщиков и сотрудников открывается сразу и не зависит от выбора гаража.
- [ ] Работать с шапкой формы сверху вниз: сначала поиск, затем вкладки и единая карточка выбранного гаража. Отдельного блока `Выбрано` над ведомостью нет. В карточке сведения разделены на группы `Гараж` (номер, люди, этажи), `Владелец` (ФИО и телефон) и `Финансы` (общий баланс и просрочка); действия расположены отдельной строкой ниже. До выбора гаража карточка не показывается.
- [ ] Результаты поиска гаражей идут по полезности: сначала точный номер, затем номера, начинающиеся с запроса, потом остальные совпадения номера и ФИО; внутри каждой группы применяется естественный порядок номеров.
- [ ] При каждом новом открытии раздела заново выбрать гараж: строка поиска, карточка выбранного гаража, локальная ведомость и история предыдущего запроса не восстанавливаются. Сохранённые в базе платежи и начисления при этом не удаляются.
- [ ] После выбора гаража задать в полях `Месяц с` и `Месяц по` любой требуемый месяц и год. Для пользователя с правом записи открытие периода запускает серверный расчёт именно этого гаража: недостающие регулярные начисления создаются, а существующие неоплаченные пересчитываются по тарифам и режимам, действовавшим в каждом месяце. Начисление с любой частичной или полной оплатой не изменяется. Деактивация услуги прекращает новые начисления, но уже выпущенный неоплаченный долг сохраняется. Пользователь только с правом чтения получает сохранённую ведомость без изменений данных.
- [ ] В карточке выбранного гаража проверить единый показатель `Баланс`: долг показывается со знаком минус, аванс — со знаком плюс, отсутствие долга и аванса — как ноль. `Просроченная задолженность` показывается отдельно как часть долга с уже наступившим сроком оплаты. Кнопка с меняющейся иконкой справа скрывает или показывает подробную таблицу; выбранное состояние запоминается отдельно для вошедшего пользователя. Если положительный баланс и просрочка существуют одновременно по разным услугам, пояснение показывает связь сумм, а таблица — услугу, месяц и остаток просрочки.
- [ ] После выбора гаража проверить период формы поступлений: по умолчанию `Месяц с` установлен на первое непогашенное начисление, а `Месяц по` — на текущий месяц. При этом список начинается с первого месяца финансовой истории и продолжается без пропусков до последнего доступного месяца, поэтому более ранние начисления и платежи можно выбрать вручную.
- [ ] У левой границы колонки `К оплате` нажать значок информации для проверки расчёта. Для новых начислений окно показывает участки месяца, даты действия режима и ставки, показания до и после, расход, пороги, формулу и сумму по каждому участку, не раздвигая строки ведомости. Для старой записи, созданной до сохранения подробных формул, значок не скрывается: окно показывает сохранённую сумму и расход и прямо сообщает, что историческая детализация недоступна; никакого повторного расчёта при просмотре не выполняется. При нескольких ставках в одном месяце система вычисляет их простое среднее арифметическое без веса по дням и применяет его ко всему месячному объёму; обе формулы видны в расшифровке.
- [ ] Для оплаты отдельной строки ввести сумму в колонке `Платеж` и нажать кнопку сохранения рядом с полем либо Enter. После успешной записи сумма в поле очищается, баланс, просроченная задолженность и ведомость обновляются без перезагрузки страницы; полностью погашенная просроченная строка сразу исчезает из расшифровки. Если платёж записан, но обновить карточку временно не удалось, система прямо сообщает об этом и не предлагает повторно создавать тот же платёж.
- [ ] Для одновременной оплаты нажать `Полная оплата` и выбрать `Полный расчет` либо конкретный месяц. Доступная сумма включает обычные услуги, объявленные сборы и нерегулярные начисления, вычитает уже имеющийся аванс по каждой строке, а повторяющееся отображение одного годового обязательства учитывает по его последнему непогашенному остатку. Перед сохранением окно показывает распределение суммы по услугам и периодам; неполную сумму можно указать вручную.
- [ ] Финансовый отчёт гаража можно открыть из строки или карточки гаража. Система сначала выбирает весь доступный период истории, а при временной недоступности определения границ всё равно открывает отчёт за стандартный период; даты можно изменить в самом окне.
- [ ] История прошлых платежей по умолчанию скрыта и не загружается при выборе гаража. Для просмотра, изменения или отмены платежа нажать `История платежей` в карточке гаража; после завершения нажать `Скрыть историю`. Действия печати квитанций в рабочей истории временно не показываются.
- [ ] Если администратор включил общую ведомость, использовать вкладки и серверную пагинацию для просмотра поступлений и выплат по всем данным; поиск гаражей остаётся доступен сверху.
- [ ] Внести поступление владельца: гараж, вид поступления, дата, месяц учета, сумма, документ и комментарий.
- [ ] Для регулярного поставщика использовать кнопку `Регулярный поставщик`: поставщик, услуга и фонд расходования берутся из его карточки, а деньги списываются с банковского счёта. Указать дату, месяц учёта, сумму, документ и комментарий.
- [ ] Для выплаты использовать единое действие `Добавить выплату`. В форме выбрать `Банк · обычная выплата поставщику` либо `Касса · эпизодическая выплата`. Для банка требуется поставщик, а услуга и фонд берутся из его карточки. Для кассы можно выбрать статью и при необходимости свободно указать получателя без создания карточки поставщика; фонд в этом варианте не выбирается.
- [ ] Банковская выплата всегда проверяется по реальному остатку банка. Если назначенного фонда недостаточно, форма заранее показывает, что фонд станет отрицательным, и требует отдельного подтверждения; это подтверждение сохраняется в истории изменений. Эпизодическая выплата проверяется по кассе. Выплата сотруднику также использует кассу и при недостатке денег показывает доступную сумму непосредственно в форме.
- [ ] Оклад активного сотрудника начисляется автоматически каждый месяц: до настроенного дня текущего месяца ставка в ведомость не входит, с этого дня появляется без ручного действия; прошлые месяцы остаются начисленными, будущие заранее не показываются. Администратор выбирает единый день от 1 до 28 во вкладке `Настройки → Рабочая дата`; изменение фиксируется в истории. Для фактической оплаты использовать `Выплатить оклад`, а для дополнительного начисления — `Начислить премию` или `Начислить штраф`: выбрать сотрудника и месяц, указать положительную сумму, при необходимости номер документа и обязательно заполнить основание. Подсказка о месячном окладе находится сразу под выбором сотрудника, а сообщение проверки — под полями формы. Премия увеличивает, а штраф уменьшает начисление за выбранный месяц; уже выплаченную сумму штрафом уменьшить нельзя.
- [ ] После премии или штрафа проверить строку сотрудника в форме выплат: в колонке услуги показывается расшифровка оклада, премии и штрафа, а в `Стоимость` — их итог. Финансовый отчёт сотрудника использует тот же итог; исполнитель и основание сохраняются в истории изменений.
- [ ] Для фактической сдачи наличных использовать только действие `Сдать кассу в банк`: указать дату, сумму и при необходимости комментарий. Фонд выбирать не требуется — это самостоятельный перевод, который уменьшает кассу и на ту же сумму увеличивает банк, не меняя остаток ни одного фонда. Обычное пополнение, изъятие или перераспределение фонда меняет назначение средств, но не их физическое расположение.
- [ ] В разделе `Фонды` сверить автоматическое назначение поступлений: каждая оплата сразу увеличивает фонд, выбранный для её вида поступления. В карточке `Общий нераспределенный пул` остаются суммы без действующего назначения, возвращённые остатки удалённых фондов и ручные изъятия. Для ручного назначения использовать `Пополнить`; каждое пополнение уменьшает общий пул, а изъятие возвращает сумму в него. Комментарий к обычному пополнению или изъятию необязателен: если его не заполнить, система сама сформирует понятное основание для истории изменений.
- [ ] Для нового назначения нажать `Создать фонд`, указать уникальное название и сохранить. Чтобы изменить название существующего фонда, открыть действие `Карточка` в его строке; остаток, операции и связи фонда сохраняются по постоянному идентификатору.
- [ ] В карточке существующего фонда проверить раздел `Услуги, оплачиваемые из фонда`: здесь справочно перечислены действующие услуги с прямой привязкой к этому фонду расходования. Изменить привязку из карточки фонда нельзя — для этого используется карточка соответствующей услуги.
- [ ] Чтобы удалить фонд, сначала переназначить все перечисленные в его карточке услуги на виды поступления других действующих фондов. Затем нажать `Удалить фонд`, проверить указанную в подтверждении сумму и ввести причину. Если у фонда есть остаток, система одной операцией вернет его в `Общий нераспределенный пул`, обнулит и удалит фонд; фонд исчезнет из рабочего списка, но автоматическое изъятие, прежние операции и запись в `Истории изменений` сохранятся.
- [ ] В таблице `Ручные перераспределения` проверять ручные пополнения, изъятия, отмены и восстановления. Автоматические назначения поступлений сразу учтены в остатках фондов, но в эту рабочую таблицу не входят и остаются доступны в общем аудите и отчётах.
- [ ] Если поступление уже израсходовано или сдано в банк, сначала отменить связанные операции; система не позволит отменой или уменьшением поступления сделать остаток кассы несогласованным.
- [ ] При открытии вкладки `Выплаты` проверить текущий месяц; для другого периода выбрать любой месяц и год в локализованном поле `Месяц`. Календарь открывается от левого края поля и полностью остаётся внутри формы, включая первый столбец месяцев и действие `Очистить`, даже на узком экране.
- [ ] В прошлом месяце форма выплат работает как архив: в таблице остаются поставщик, услуга, входящий и исходящий баланс, стоимость и оплаченная сумма. Оперативные колонки `Текущий размер фонда`, `Действие` и кнопка оплаты в строке не показываются. В текущем и будущем месяце они доступны как обычно.
- [ ] В колонке `Текущий размер фонда` сверять актуальную доступную сумму связанного фонда после проведённых выплат. Отрицательное значение выделяется и означает подтверждённое превышение фонда при банковской выплате.
- [ ] В форме выплат сверить `Входящий баланс` и `Исходящий баланс` по каждому получателю и услуге. Задолженность показывается отрицательной суммой, аванс — положительной, отсутствие остатка — нулём; эти учетные колонки отображаются нейтральным цветом.
- [ ] В текущем или будущем месяце проверить цвет в колонке `Текущий размер фонда`: отрицательный остаток показывается красным, положительный — зелёным. Учётные колонки входящего и исходящего баланса остаются нейтральными.
- [ ] Не создавать ручную операцию переноса между месяцами: исходящий долг или аванс автоматически становится входящим остатком следующего месяца для той же пары получатель + услуга.
- [ ] Для разового начисления по гаражу нажать `Добавить начисление`. В поле `Основание` можно выбрать готовое значение из справочника нерегулярных платежей или ввести свой текст. При выборе готового значения подставляется его сумма; для произвольного основания сумму нужно указать вручную. Комментарий необязателен, основание сохраняется в начислении и истории изменений.
- [ ] Нерегулярное начисление из справочника отображается в платежах выбранного гаража, пока не погашено полностью. После частичной оплаты строка показывает только оставшуюся сумму; после полной оплаты или деактивации основания строка исчезает при обновлении расчёта. Деактивация не удаляет финансовую историю.
- [ ] Для штрафа использовать отдельное действие `Начислить штраф` в карточке гаража: указать произвольную положительную сумму, месяц и обязательную причину. Система использует системный вид поступления `Штраф`, добавляет начисление в ведомость и сохраняет исполнителя и причину в истории изменений. Без права `payments.write` действие недоступно.
- [ ] Создать начисление поставщику для сверки обязательств и выплат. Сначала выбрать поставщика: поле `Услуга` заполнится из его карточки автоматически, а связанный `Фонд расходования` будет показан непосредственно под услугой; эти значения недоступны для произвольного изменения. Комментарий для обычного ручного начисления необязателен; при изменении автоматически созданного начисления он нужен как причина корректировки. Если услуга или фонд не настроены, сначала исправить карточку услуги, затем закрепить эту услугу за поставщиком. На узком экране подписи, поля, сообщения проверки и кнопки выстраиваются в одну колонку.
- [ ] Не запускать регулярные начисления вручную: система автоматически обрабатывает активные регулярные услуги и объявленные сборы. Действие `Добавить начисление` использовать только для разового начисления по гаражу; штраф оформлять отдельным действием `Начислить штраф`.
- [ ] При открытии гаража ведомость автоматически согласует расчёт с фоновым формированием начислений. Если оба действия начались одновременно, система последовательно завершит их, не создаст дубликат и покажет актуальные суммы; обновлять страницу из-за технического конфликта не требуется.
- [ ] Внести показания воды или электричества по гаражу. Электроэнергия на экране показаний, в расходе и порогах тарифа измеряется в `кВт·ч`; `кВт` обозначает мощность и для этих значений не используется. Текущий месяц доступен сотруднику с правом записи платежей; прошлый и будущий месяцы доступны только с отдельным правом `Показания вне текущего месяца`.
- [ ] При сохранении показания система применяет все версии услуги и тарифа, действующие в выбранном месяце: фиксированные, счётчиковые и пороговые участки складываются в одну сумму, а расход при смене режима внутри месяца распределяется пропорционально дням. Система создаёт отсутствующее начисление и показывает его в форме поступлений вместе с раскрываемой формулой. Если по этому виду поступления уже есть аванс, он сразу распределяется на новое начисление. Поэтому ввод прошлого или будущего месяца не подменяет его текущей ставкой и не меняет правила других периодов.
- [ ] Проверять предупреждения о разрыве истории счетчиков.
- [ ] Для ввода или изменения прошлого либо будущего месяца использовать окно `Другой учетный период`, указать обязательную причину и иметь отдельное право `Показания вне текущего месяца`. Без этого права сервер не сохранит данные выбранного периода; причина попадёт в историю изменений.
- [ ] Если новое показание меньше предыдущего, не исправлять его как обычную ошибку: в открывшемся окне `Оформить замену счетчика?` указать номер и начальное показание нового прибора, конечное показание снятого прибора, дату и причину замены. Для текущего месяца достаточно права записи платежей и показаний; замена в любом другом месяце дополнительно требует права `Показания вне текущего месяца`. В месяце замены система сложит расход обоих приборов, а следующие месяцы продолжит от нового счетчика.
- [ ] При одновременной работе с одним счетчиком обновить таблицу после сообщения о конфликте: система сохраняет только одну замену и не создает два действующих прибора. Показание, которым оформлена замена, нельзя отдельно отменить без корректировки самой истории приборов.
- [ ] После изменения показания проверить автоматически пересчитанное связанное начисление. Если оно уже полностью или частично оплачено, система оставит показание и сумму без изменений и сообщит о конфликте; сначала исправьте оплату штатной операцией или согласуйте отдельную корректировку.
- [ ] Отменять ошибочные операции только через действие отмены с обязательной причиной.
- [ ] Отмененные операции исключаются из активных списков, сводки и расчетов задолженности.
- [ ] При изменении платежа, начисления, выплаты или показания проверить окно `было -> стало`; пустое новое значение может сохраниться сразу, а изменение существующего значения требует подтверждения.
- [ ] После отмены или восстановления операции проверить раздел "История изменений" по гаражу, контрагенту, месяцу или документу.

## 7. Импорт Access

Раздел "Импорт Access" используется для безопасной проверки старой базы.

Максимальный размер одного файла `.accdb` или `.mdb` — 50 МБ. Интерфейс проверяет размер сразу после выбора и не отправляет слишком большой файл на сервер.

- [ ] Перед импортом сделать backup PostgreSQL.
- [ ] Выбрать `.accdb` или `.mdb`.
- [ ] Запустить dry-run.
- [ ] Дождаться, пока фоновый статус сменится с «В очереди»/«Выполняется» на итоговый; во время проверки можно переходить по другим разделам.
- [ ] Проверить статусы checks: пройдено, предупреждение, ошибка.
- [ ] Если в checks есть "Повторная проверка файла", сверить, что это осознанная повторная загрузка той же Access-БД, а не случайный дубль.
- [ ] Проверить блок "Reader Access": если он показывает "Не настроен", фактическое чтение `.accdb/.mdb` еще не подключено.
- [ ] Проверить лог запуска: шаг получения файла, расчет hash, проверки `check_*` и финальный итог `dry_run_finished`.
- [ ] После фактического переноса проверить вкладку "Создано": там должны быть видны записи, созданные выбранным запуском Access, и их статус rollback.
- [ ] Скачать отчет кнопкой "Скачать отчет JSON".
- [ ] После успешного dry-run нажать "Запросить импорт", указать причину и подтвердить, что backup PostgreSQL создан.
- [ ] Помнить, что до подключения reader Access заявка только фиксируется в истории и не переносит строки в рабочую базу.
- [ ] Если заявка на импорт отправлена ошибочно, нажать "Отменить заявку" и указать причину; это не rollback данных.
- [ ] Не менять исходную Access-БД вручную.
- [ ] Не переносить данные вручную, если dry-run показывает ошибки.
- [ ] Если есть предупреждение про ACE-драйвер или Microsoft Access, передать разработчику JSON-отчет без исходной базы.

## 8. Отчеты

Раздел "Отчеты" содержит восемь рабочих вкладок: `Консолидированный`, `По гаражам`, `По выплатам`, `Поступления`, `Оплаты из кассы`, `Сдача кассы в банк`, `Сборы` и `Изменение фондов`.

- [ ] На всех вкладках с периодом можно одним действием выбрать `Текущий месяц`, `Текущий год` или `Предыдущий год`. Кнопка заполняет обе границы периода; выбранный быстрый период выделяется. Для отчёта по сборам эти действия не показываются, потому что у него нет фильтра по датам.
- [ ] Консолидированный отчет: выбрать месяц начала и окончания. Для каждого месяца сверить параллельные списки поступлений и выплат по наименованиям, итоговую разницу и остаток банковского счета на начало и конец месяца. Сдача кассы в банк увеличивает остаток счёта, регулярная выплата уменьшает, а эпизодическая выплата из кассы не влияет на банк независимо от наличия чека. PDF формируется в альбомной ориентации на русском языке: длинные наименования переносятся внутри строк, заголовки месяца и колонок повторяются на продолжении таблицы, а внизу каждой страницы указан её номер.
- [ ] `По гаражам`: выбрать период, гаражи, владельцев, виды поступлений и нужную детализацию. Поле `Гаражи` раскрывает выпадающий список сразу после фокуса и сокращает его по мере ввода номера или ФИО владельца; несколько записей отмечаются флажками. Пустой выбор и кнопка `Все` формируют отчёт по всем гаражам. Чтобы повторно использовать подборку, выбрать гаражи, нажать `Создать быстрый список` и указать название. Именованный список доступен всем пользователям отчётов, его можно применить из поля `Быстрый список`, переименовать или обновить текущим составом; при удалении требуется причина, которая сохраняется в истории изменений.
- [ ] Отчет по поступлениям: выбрать даты и гаражи; несколько гаражей отмечаются флажками после поиска по номеру или владельцу. При поиске по номеру точное совпадение показывается первым, затем номера с тем же началом и остальные совпадения; внутри групп действует естественный порядок, поэтому `21А2` находится раньше `21А10`. По умолчанию части одной квитанции или полной оплаты объединяются в одну строку с общей суммой и перечнем назначений. Это относится и к полным оплатам, сохранённым до появления единого номера квитанции: последовательные части одной такой оплаты распознаются отдельно от обычных и более поздних платежей. Кнопка `Показать отдельные платежи` раскрывает операции, а `Сгруппировать платежи` возвращает сводный вид. XLSX и PDF сохраняют текущий режим экрана. Строка `ИТОГО` показывает сумму всех отфильтрованных активных платежей за период; переключение режима и переход на другую страницу не добавляют эти суммы повторно.
- [ ] Отчет по выплатам: выбрать даты, найти поставщиков и/или сотрудников в общем поле и отметить нужные записи флажками, затем выбрать услуги и режим строк. Стартовый баланс должен присутствовать только в календарном месяце начала учёта поставщика; в более позднем периоде он не должен появляться как новое начисление. В режиме `Все` сверить начисление и выплату одного месяца в общей строке; режимы `Начисления` и `Выплаты` использовать для подробной расшифровки.
- [ ] В любом фильтре отчёта с флажками проверить карточки выбранных записей: одну запись можно снять отдельно, все — кнопкой очистки. Пустой выбор означает отчёт по всем записям; экран, XLSX и PDF используют один состав флажков.
- [ ] При медленном открытии финансового отчёта дождаться заполнения каркаса итогов и таблицы. Календарь периода доступен уже во время загрузки и должен раскрываться полностью, без обрезания границей окна.
- [ ] Пользователь с правом `audit.read` может перейти из финансового отчёта контрагента в отфильтрованную историю изменений. Без этого права раздел перехода полностью скрыт и не занимает место в отчёте.
- [ ] При сверке поставщика проверить карточку `Входящий остаток`: она учитывает стартовый баланс один раз и все активные начисления и выплаты до начала выбранного периода. В строке входящего остатка колонки `Начислено` и `Оплачено` остаются пустыми, поэтому итоги периода содержат только операции выбранных месяцев; отрицательное значение учитывается как аванс.
- [ ] `Оплаты из кассы` и `Сдача кассы в банк`: сверить движение наличных и поступление той же суммы на банковский счет.
- [ ] `Сборы`: при первом открытии убедиться, что показаны все действующие объявленные сборы, включая новый сбор без начислений и оплат. Для отдельного сбора выбрать его название из подсказок фильтра, затем сверить начислено, оплачено, остаток и список гаражей.
- [ ] `Изменение фондов`: сверить фонд, вид изменения, колонку `Изменение, руб.`, сумму до/после, пользователя и комментарий. Поступление автоматически появляется как пополнение назначенного фонда. Любая выплата поставщику — из банка или кассы — появляется как изъятие с названием поставщика и услуги; отмена возвращает сумму, восстановление снова списывает её. Кассовая выплата сотруднику фонд поставщика не затрагивает. В XLSX используется та же русская подпись, в PDF — `Izmenenie, rub.`.
- [ ] Режим строк `all` показывает начисления и оплаты/выплаты.
- [ ] Режим `accruals` показывает только начисления.
- [ ] Режим `payments` показывает только оплаты или выплаты.
- [ ] В каждой вкладке использовать `Скачать XLSX` или `Скачать PDF`: выгрузка применяет тот же период, фильтры и сортировку, что экран.
- [ ] Для отчёта `По гаражам` сравнить экран с XLSX/PDF: порядок колонок, строки, месяц `мм.гггг`, итоговые суммы и пояснение должны совпадать; лишней колонки владельца быть не должно.
- [ ] При смене страницы или сортировки сверять общие итоги: они относятся ко всей отфильтрованной выборке, а не только к видимым строкам.
- [ ] Если отчет не сходится, проверить период, фильтры, стартовые балансы, регулярные начисления и показания счетчиков.

## 9. История изменений

Раздел "История изменений" доступен пользователям с `audit.read`.

- [ ] Смотреть последние действия пользователей и системные события.
- [ ] Искать по действию, сущности или описанию.
- [ ] Использовать фильтры раздела, действия, объекта, пользователя, периода и быстрые категории "Только удаления", "Только восстановления", "Только финансы".
- [ ] Открывать карточку события кнопкой "Открыть", чтобы увидеть `было`, `стало`, причину или комментарий и связанные данные.
- [ ] Проверять связанный гараж, контрагента, расчетный месяц или документ, если нужно понять, какая запись повлияла на расчеты.
- [ ] Для удаления, архивирования, восстановления, отмены и ручных корректировок обязательно читать причину: она объясняет, почему действие было выполнено.
- [ ] Проверять события входа, смены пароля, создания пользователей, платежей, импорта и отмен.
- [ ] Скачать CSV через кнопку "Скачать CSV".
- [ ] Не использовать историю изменений как источник полного финансового отчета: для этого есть раздел "Отчеты".

## 10. Что нового

Раздел "Что нового" показывает историю релизов из `GET /api/app-releases`.

- [ ] После обновления открыть раздел и проверить новую версию.
- [ ] Прочитать описание, если изменились правила работы.
- [ ] Если раздел не загрузился, сообщить администратору и проверить troubleshooting.

## 11. Закрытие месяца

Закрытие месяца в GarageBalance означает сверку и сохранение контрольных отчетов. Оно не блокирует период и не создает отдельную финансовую операцию.

- [ ] Выполнить порядок из `docs/monthly-cycle-checklist.md`: backup, справочники, тарифы, счетчики, начисления, поступления, выплаты, касса, банк и фонды.
- [ ] Проверить, что поступления закрывают старейшие начисления того же гаража и вида поступления. В форме платежей значение `Оплачено` по строке не должно превышать `К оплате`, а остаток по каждой строке и по периоду должен показываться единым `Балансом`: долг со знаком минус, аванс со знаком плюс.
- [ ] Создать следующее начисление того же вида и убедиться, что сохранённый аванс применился автоматически, уменьшил долг и не был повторно записан как новая оплата.
- [ ] После частичной оплаты системной услуги, например `Вода`, внести оставшийся долг в той же строке. Платёж должен сохраниться по указанному в строке виду поступления без открытия справочников и без сообщения `Не найден вид поступления`.
- [ ] В истории платежей открыть платёж, изменить только комментарий и один раз нажать `Сохранить`. Изменение должно записаться без второго подтверждения; при корректировке суммы, даты, месяца или документа подтверждение должно сохраниться.
- [ ] Проверить карточку гаража с задолженностью: отдельной кнопки `Перенести задолженность` быть не должно. Долг учитывается по сохранённым начислениям и платежам без ручной операции между месяцами.
- [ ] Убедиться, что частично оплаченный годовой взнос продолжает показываться до полной оплаты.
- [ ] Сверить следующий месяц: долг или аванс поставщика переносится только внутри той же пары `поставщик + услуга`; ручную строку переноса создавать не нужно.
- [ ] Сверить остаток фонда расходования по услуге: последующая выплата должна уменьшить его ровно на сумму операции, отмена — вернуть сумму, а восстановление — списать повторно без дублирования.
- [ ] Проверить все восемь вкладок отчетов по одному периоду и сохранить нужные XLSX/PDF вне Git.
- [ ] Записать спорные строки и контрольные суммы. Если старый месяц исправляется позже, использовать штатное изменение, отмену или восстановление с причиной и затем повторить сверку последующих месяцев.
