# Безопасное возобновление годовых начислений

## Источники и границы

Задание: восстановить ежегодные начисления GarageBalance и опубликовать исправления. Исправления повторного расчёта, ручной отмены и периода платежей опубликованы в 1.185.42 / PR22. Этот этап готовит проверку финансового эффекта и защищённое снятие отдельной годовой приостановки.

Текущий исходный срез: master 5f0dd4fc. Изучены AnnualAccrualHoldReleaseEngine, selective maintenance protocol и recovery, тарифный расчёт, API годовых платежей и история изменений. При включённом hold существующий API не показывает будущие начисления, поэтому нулевой preview нельзя считать нулевым эффектом снятия hold.

## Решения

- Не снимать live hold и не исправлять реальные начисления до оценки охвата и безопасной квалификации.
- Прогноз только читает согласованный снимок; не вызывает генерацию начислений и не меняет настройки, аудит или роли.
- Отчёт не содержит владельцев и контактных данных. Неопределённый расчёт обозначается явно и блокирует release.
- Release связывается с точным финансовым прогнозом, годом, источником и версиями настроек. Изменившиеся входы требуют нового плана.
- Прямой staging execute без закрытого scoped permit остаётся запрещён. Не добавлять флаг обхода, новые права БД или доступ через чужую CRM.
- После неизвестного исхода recovery только доказывает commit/rollback; повторная SQL-операция запрещена.
- Миграции и frontend не планируются. Если контракт затронет их, пересмотреть проверки до публикации.

## Критерий готовности и риски

Готовность процедуры не означает, что live приостановка уже снята. Прогноз обязан совпадать с поддержанными правилами расчёта; неизвестные тарифные/исторические случаи не превращаются в нулевые суммы. Synthetic fixtures не заменяют квалификацию установленного VPS. Backup success не заменяет restore verification. Пользовательские данные, планы и receipts не публикуются в Git или CI.

## История выполнения

- 09.11.2026: подтверждено, что annual release ещё не подключён к защищённому staging-протоколу и безусловно отклоняется. Созданы отдельные ветки для прогноза, runner/recovery и Linux fixture, начата интеграция CLI. Никакие live hold, начисления, роли или права не менялись. Полный gate нового этапа ещё не выполнялся.

- 09.11.2026: выявлены дополнительные причины: batch использовал тариф исходного месяца вместо перенесённого старта; worker не догонял годовые за предыдущие месяцы текущего года. Исправления и parity tests готовятся отдельно. Прогноз на фиксированных/подушных синтетических сценариях прошёл первые 7 PostgreSQL тестов; это не финальный gate объединённого кода.

- 09.11.2026: объединённый focused gate прошёл 63 теста PostgreSQL/CLI/прогноза; независимое ревью не выявило обходов протокола. Первый полный прогон (4316 тестов) обнаружил два случая совместимости явного планового catalog-запуска и несинхронизированный индекс новых документов. Ограничение даты оставляется только для настоящего catch-up; прежние финансовые ожидания сохраняются. Добавлены диагностические проверки recovery и точный индекс документации. Окончательный полный gate и реальный Linux/systemd CI ещё впереди.

- 09.11.2026: окончательный локальный gate: build без предупреждений/ошибок, 4325 passed и один существующий S3 integration skip из 4326; coverage 90,03% строк / 76,37% ветвей. Дополнительно 207 финансовых focused и 8 CLI/документационных проверок; старые catalog/showcase тесты не ослаблены. Format, dependency audit (5 проектов), privacy (1694 файла), отсутствие pending migrations, idempotent SQL, 5 staging-target tests, 21 shell script и 26 bash-блоков CI прошли. Локального Docker нет: выполнен только статический distribution gate; реальный Docker и Linux/systemd обязательны в CI. Frontend локально не запускался: его код и API-контракт не менялись, полный CI сохранён. Независимый review уточнил recovery guidance и strict shell manifest; обе правки внесены. Task-owned процессов и новых временных PostgreSQL БД после прогона нет; исходные 11 чужих test DB и shared MCP оставлены нетронутыми.
