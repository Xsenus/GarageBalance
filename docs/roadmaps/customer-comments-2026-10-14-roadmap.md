## Решения и границы

- Ошибку п. 1–2 воспроизвести на синтетических данных через HTTP API перед исправлением; расчёт каждого месяца выполнять по тарифным версиям этого месяца.
- Стартовое значение счётчика по умолчанию относится к концу месяца, предшествующего «Учитывать с». Поле «Дата подключения» убрано из карточки гаража. Отдельное подключение услуги позже начала учёта сохраняется в «Показаниях» (кнопка «Подключить услугу»).
- Перенос существующего подключения к началу учёта без явной даты разрешён только путям, которые требуют прав на корректировку начальных данных: исправление «Учитывать с» и исправление стартового значения в «Показаниях». Карточка гаража для подключённого счётчика передаёт дату начала учёта явно, поэтому сохраняется прежняя проверка прав.
- Изменение стартового значения сразу пересчитывает расход и неоплаченные начисления; оплаченные начисления защищены прежним правилом.
- Пункты 4 и 6 — операции с рабочими данными на VPS. Из облачной среды доступа к VPS нет; решения пользователя от 14.10.2026 (очистку отложить до его проверки, историю показаний сохранить) остаются в силе.

## Пункты документа

### Пункт 1 Изменения тарифов не доходят до «Платежей»

- [x] Воспроизвести: изменение ставки через тарифную сетку пересчитывает неоплаченный октябрь (18 × 9,00 = 162). Найденная причина устаревших и неверных сумм — расчёт формы за несколько месяцев по тарифу последнего месяца (см. п. 2).
- [x] Исправить загрузку тарифных версий на весь период и помесячный выбор тарифа; регрессии SQLite/PostgreSQL.
- [acceptance] Пользователь проверяет изменение тарифа с 01.10 и форму «Платежи» на опубликованном выпуске.

### Пункт 2 Не подтянулись сентябрьские электроэнергия и мусор

- [x] Воспроизвести: при периоде 09–10 сентябрь пересчитывался по октябрьским версиям; неоплаченные электроэнергия и вода отменялись как нулевые, мусор получал «Не задан тариф». Оплаченная вода у заказчика уцелела, потому что оплаченные строки не пересчитываются.
- [x] Исправить и защитить регрессией SQLite/PostgreSQL (периоды 09–10 и 09–12, отсутствие отменённых строк).
- [x] Однократно пересчитать неоплаченные начисления, уже искажённые прежним расчётом за период: гаражи с такими пересчётами в аудите пересчитываются при запуске от самого раннего затронутого месяца; оплаченные строки защищены; итог в аудите и отметке настроек.
- [acceptance] Пользователь открывает «Платежи» проблемного гаража и проверяет восстановление сентябрьских начислений.

### Пункт 3 Первый месяц формы «Показания»

- [x] Backend: стартовое значение без даты относится к месяцу перед «Учитывать с» (создание гаража, исправление карточки, новый эндпоинт `PUT api/finance/meter-connections/start-value`); при исправлении «Учитывать с» подключения переносятся вместе с ним.
- [x] Frontend: в «Показаниях» месяц стартового значения показан первым и редактируется с подтверждением; в карточке гаража нет поля «Дата подключения», подсказка называет месяц базы.
- [x] Тесты: пример заказчика 320 → 342 = 22, исправление старта 330 и мгновенный пересчёт, перенос «Учитывать с», перенос поздней даты подключения, валидация, права, ошибки сохранения, UI-сценарии.
- [x] Гаражи после начала нового учёта показаний (граница «Начало учёта», без отдельного подключения): база ставится на месяц перед более поздней из дат — «Учитывать с» или начало нового учёта, показывается первым месяцем, редактируется в ячейке с пересчётом; карточка гаража показывает тот же месяц. Граница и история показаний не меняются.
- [acceptance] Пользователь проверяет пример с новым гаражом на опубликованном выпуске.

### Пункт 5 Сценарии замены счётчика

- [x] Проверить три сценария: старт нового больше старого — 80, равен — обычный расчёт (60), меньше — пересечение дважды (90). Текущая формула уже даёт эти значения; добавлена сквозная регрессия с суммой начисления.

## Риски и вопросы

- Если «Учитывать с» позже начала нового учёта показаний, база следует «Учитывать с»; если раньше — остаётся перед началом нового учёта, потому что прежние показания перенесены в историю.
- Существующие гаражи с подключением счётчика позже «Учитывать с» (например, дата 18.10 при начале в сентябре) сами не переносятся: исправление стартового значения в «Показаниях» или исправление «Учитывать с» ставит базу на месяц перед началом учёта.
- Пункты 4 и 6 требуют доступа к VPS и решения пользователя о перечне записей.
