# Полная оптимизация производительности и стабильности GarageBalance

## Источники

- Запрос заказчика от 29.07.2026: каждый раздел должен работать максимально быстро, стабильно и без ошибок.
- Реальные nginx-, systemd- и PostgreSQL-метрики VPS после развёртывания версии `0.869.0`.
- Действующие требования `AGENTS.md` по серверной пагинации, PostgreSQL-агрегациям, индексам, frontend-рендерингу, тестам и развёртыванию.
- Текущие backend/frontend-тесты, production bundle budget и инфраструктура GitHub Actions/VPS.
- Активные roadmaps замечаний заказчика; их незавершённые пункты приёмки не переносятся и не расширяют этот roadmap.

## Допущения и решения

- Оптимизация выполняется по измерениям: сначала наблюдаемость и воспроизводимый baseline, затем устранение подтверждённых узких мест.
- Быстродействие не должно ослаблять права, аудит, финансовую точность, защиту данных и проверку конкурентных изменений.
- Запросы записи не повторяются автоматически. Повтор и кэширование допустимы только для безопасных чтений с явными правилами актуальности.
- Фильтрация, сортировка, пагинация и агрегация больших наборов выполняются PostgreSQL; клиент не загружает полные финансовые таблицы.
- Справочники можно кэшировать и объединять параллельные одинаковые загрузки, но кэш обязан сбрасываться после изменений и завершения сессии.
- Оптимизация VPS включает приложение, PostgreSQL, nginx/Cloudflare и диагностику, но изменения DNS/Cloudflare применяются только после проверки текущих настроек и риска.
- Каждая завершённая группа получает тесты, локальную PostgreSQL-проверку, release note при видимом эффекте и отдельный коммит. Push выполняется только по отдельной команде.

## Открытые риски и вопросы

- Рабочая БД пока мала (около 29 МБ), поэтому часть узких мест проявится только на обезличенном performance seed.
- `pg_stat_statements` сейчас не включён; без него нельзя честно ранжировать SQL по накопленному времени.
- Реальные пользовательские маршруты нужно снять во время работы, отделяя их от интернет-сканеров.
- Cloudflare и IPv6 могут давать задержку вне приложения; изменение DNS требует проверки текущей панели Cloudflare.
- Чрезмерное кэширование финансовых данных опасно устаревшими итогами, поэтому оно допускается только с явной инвалидизацией/версией.
